# Hub v1.2.4 upgrade — IBM 1010 fix (2026-09-14)

## Why
The 2026-09-12 verification showed `/v1/qpu/backends` and `/v1/qpu/usage`
returning 502 with Cloudflare 1010 `browser_signature_banned`. Root cause:
IBM's edge bans Python stdlib's TLS signature — not the key, not the
headers. v1.2.4 adds an opt-in curl transport with a browser-like TLS
fingerprint (same trick that got the bridge relay past bot checks).

## Steps
1. `git pull` (or fresh clone) `https://github.com/FormatX66/medic-model-hub`
   — root tree is now v1.2.4.
2. Back up `C:\Users\bruce\MedicHub\hub\.env` (copy to `.env.bak-20260914`).
3. Copy the repo's `server/`, `tests/`, `Dockerfile`, `docker-compose.yml`,
   `.env.example`, `README.md`, `CHANGELOG.md` over
   `C:\Users\bruce\MedicHub\hub` — **do not overwrite `.env`**.
4. Add to the hub `.env`: `QPU_HTTP_CLIENT=curl`
5. `docker compose up -d --build` (Dockerfile now installs curl).
6. Read-only verification:
   - `GET http://localhost:8090/health` (expect 200, version 1.2.4)
   - `GET http://localhost:8090/v1/qpu/backends` (expect 200 — the fix)
   - `GET http://localhost:8090/v1/qpu/usage` (expect 200 — real quota)
7. Do NOT submit any QPU hardware job.
